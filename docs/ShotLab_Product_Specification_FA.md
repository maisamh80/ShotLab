# مشخصات محصول و نقشهٔ توسعهٔ ShotLab

> یادداشت نسخهٔ ۰.۲: تصمیم جدید محصول، بخش‌های مربوط به تحلیل و پیشنهاد هوش
> مصنوعی در این سند را لغو می‌کند. نسخهٔ اجرایی فقط پالت پنج‌رنگ را استخراج
> می‌کند و تمام اطلاعات توصیفی به‌صورت دستی وارد می‌شوند. این یادداشت بر
> بخش‌های قدیمی‌تر AI در ادامهٔ سند اولویت دارد.

**نسخه سند:** 1.0

## ۱. تعریف محصول

ShotLab یک نرم‌افزار دسکتاپ و کاملاً لوکال برای ساخت کتابخانه‌ای شخصی از
فریم‌های سینمایی، متادیتاها و تحلیل‌های بصری است. این نرم‌افزار به کارگردان،
فیلم‌بردار، طراح تولید، لایتر، Look Development Artist، Colorist و دیگر
هنرمندان اجازه می‌دهد از فیلم‌ها و تصاویر مرجع خود، یک دیتابیس قابل جست‌وجو و
قابل توسعه بسازند.

ShotLab از نظر کارکرد کلی از ابزارهایی مانند ShotDeck الهام می‌گیرد، اما محصولی
مستقل با Taxonomy، تجربهٔ کاربری و ساختار دادهٔ اختصاصی خود خواهد بود.

تمام پردازش‌ها، تصاویر و اطلاعات پروژه روی سیستم کاربر باقی می‌مانند و استفاده
از قابلیت‌های اصلی به سرویس آنلاین وابسته نیست.

## ۲. هدف اصلی

کاربر باید بتواند:

1. یک پروژه با نام دلخواه ایجاد کند.
2. یک فایل ویدئویی را فقط برای جلسهٔ استخراج فریم باز کند.
3. ویدئو را روی Timeline پخش و پیمایش کند.
4. در لحظهٔ دلخواه، فریم جاری را Capture کند.
5. تحلیل‌های فوری و پیشنهادهای هوش مصنوعی را مشاهده کند.
6. اطلاعات پیشنهادی را اصلاح یا تکمیل کند.
7. فریم را تأیید و به کتابخانهٔ پروژه اضافه کند.
8. فریم‌های ثبت‌شده را ویرایش، جست‌وجو، مقایسه و برای ساخت رفرنس استفاده کند.
9. از پروژه‌ها Backup بگیرد و آن‌ها را روی نصب دیگری از ShotLab بازیابی کند.

## ۳. اصول بنیادین محصول

### ۳.۱. نرم‌افزار دسکتاپ واقعی

محصول نهایی باید یک نرم‌افزار قابل نصب باشد، نه یک Web App که در مرورگر اجرا
شود. کاربر نباید Python، FFmpeg، مدل‌های AI یا Dependency دیگری را به‌صورت دستی
نصب یا تنظیم کند.

Installer باید تمام اجزای مورد نیاز را نصب و پیکربندی کند.

### ۳.۲. پردازش لوکال و حفظ حریم خصوصی

- تحلیل تصویر و ویدئو به‌صورت پیش‌فرض روی سیستم کاربر انجام می‌شود.
- اطلاعات پروژه بدون اجازهٔ صریح کاربر به سرویس خارجی ارسال نمی‌شوند.
- نرم‌افزار باید بدون اتصال دائمی به اینترنت قابل استفاده باشد.

### ۳.۳. ویدئوی اصلی خارج از دیتابیس

به دلیل حجم بالای فایل‌های ویدئویی:

- فایل ویدئوی اصلی هرگز داخل دیتابیس ذخیره نمی‌شود.
- فایل ویدئو داخل پوشهٔ پروژه یا Backup عادی کپی نمی‌شود.
- مسیر دائمی فایل ویدئو نیز در دیتابیس ذخیره نمی‌شود.
- مسیر فایل فقط در حافظهٔ موقت همان جلسه‌ای نگهداری می‌شود که کاربر در حال
  پخش و استخراج فریم‌هاست.
- پس از پایان جلسه، ShotLab همچنان تمام فریم‌های تأییدشده و اطلاعات آن‌ها را
  نمایش می‌دهد، اما برای ادامهٔ Capture از همان ویدئو، کاربر باید فایل اصلی را
  دوباره انتخاب کند.
- ShotLab می‌تواند برای تشخیص درست فایل، یک Fingerprint غیرقابل بازسازی شامل
  مدت، ابعاد، Frame Rate، اندازهٔ فایل و Hash نمونه‌ای ذخیره کند؛ این اطلاعات
  خود ویدئو یا مسیر آن را در بر نمی‌گیرند.
- هنگام انتخاب مجدد ویدئو، نرم‌افزار Fingerprint را بررسی می‌کند و در صورت
  عدم تطابق به کاربر هشدار می‌دهد.

تمام Captureها باید Timecode دقیق منبع را نگهداری کنند تا در جلسهٔ بعدی نیز
موقعیت اصلی فریم مشخص باشد.

### ۳.۴. کنترل نهایی در اختیار کاربر

هوش مصنوعی فقط پیشنهاد می‌دهد. هیچ تحلیل AI بدون امکان مشاهده، اصلاح و تأیید
کاربر به‌عنوان اطلاعات نهایی ذخیره نمی‌شود.

ShotLab دو محیط اصلی دارد.

### ۴.۱. محیط Capture

- Timeline
- کنترل‌های پخش و پیمایش

- Capture فریم
- نمایش Captureهای تأییدشده روی Timeline
- تحلیل سریع
- تحلیل هوشمند
- Inspector برای بررسی و اصلاح اطلاعات
- ویرایش Captureهای قبلی

### ۴.۲. محیط Library

محیطی برای استفاده از اطلاعات ثبت‌شده:

- نمایش تمام پروژه‌ها
- جست‌وجوی سراسری
- فیلتر متادیتاها
- مشاهدهٔ صفحهٔ هر پروژه
- مشاهدهٔ Color Script
- مشاهده و مقایسهٔ فریم‌ها
- افزودن تصاویر مستقل
- ساخت Reference Board
- Export، Backup و Import

### ۵.۲. اطلاعات اختیاری

## ۶. جریان کاری Capture

### ۶.۱. انتخاب ویدئو

کاربر در پروژه، گزینهٔ «شروع جلسهٔ Capture» را انتخاب و فایل ویدئویی را از
کامپیوتر خود باز می‌کند.

ShotLab:

- اطلاعات فنی ویدئو را می‌خواند.
- Fingerprint را با پروژه مقایسه می‌کند.
- فایل را بدون کپی‌کردن و بدون افزودن آن به دیتابیس، مستقیماً از محل لوکال
  پخش می‌کند.
- اگر Codec قابل پخش مستقیم نباشد، با اجازهٔ کاربر یک Proxy موقت ایجاد می‌کند.
- Proxy نیز جزو دیتابیس یا Backup پروژه نیست و قابل پاک‌سازی است.

### ۶.۲. Player و Timeline

کاربر باید بتواند:

- Play و Pause کند.
- روی Timeline جابه‌جا شود.
- یک فریم جلو یا عقب برود.
- چند ثانیه جلو یا عقب برود.
- سرعت پخش را تغییر دهد.
- Timecode دقیق را ببیند.
- Captureهای تأییدشده را به‌صورت Marker روی Timeline مشاهده کند.
- با کلیک روی Marker یک Capture قبلی را باز و ویرایش کند.

برای ویدئوهای Variable Frame Rate، Timecode باید براساس PTS و Time Base ویدئو
محاسبه شود و صرفاً حاصل‌ضرب FPS در زمان نباشد.

### ۶.۳. Capture

کاربر با دکمه یا Shortcut، فریم جاری را Capture می‌کند.

پیشنهاد میان‌برها:

| کلید | عملکرد |
|---|---|
| `Space` | پخش یا توقف |
| `C` | Capture فریم جاری |
| `←` و `→` | حرکت یک فریم |
| `J` و `L` | حرکت چند ثانیه‌ای |
| `Esc` | بستن Draft |

### ۶.۴. Inspector به‌جای Popup مسدودکننده

بعد از Capture، اطلاعات در یک Inspector ثابت در کنار Player نمایش داده می‌شوند.
این روش بر Popup ترجیح دارد زیرا:

- Timeline و تصویر ویدئو همچنان قابل مشاهده‌اند.
- مقایسهٔ فریم با منبع آسان‌تر است.
- ثبت پیاپی فریم‌ها سریع‌تر انجام می‌شود.
- همان Inspector برای ویرایش Captureهای قبلی استفاده می‌شود.

Capture ابتدا یک Draft است و تا قبل از تأیید وارد دیتابیس اصلی نمی‌شود.

### ۶.۵. تحلیل دو مرحله‌ای

#### مرحلهٔ اول: تحلیل فوری

این مرحله باید تقریباً بلافاصله انجام شود:

- استخراج تصویر
- Timecode
- Frame Number یا PTS
- پالت رنگ
- روشنایی
- کنتراست
- اشباع
- Sharpness
- Warm، Cool یا Neutral
- Low-Key، High-Key یا Balanced

#### مرحلهٔ دوم: تحلیل هوشمند

نتایج AI می‌توانند چند ثانیه بعد به‌تدریج در Inspector ظاهر شوند:

- اندازهٔ نما
- زاویهٔ دوربین
- Interior یا Exterior
- زمان روز
- ترکیب‌بندی
- عمق میدان
- نوع و کیفیت نور
- جهت احتمالی Key Light
- Mood
- Subject
- Environment
- Objects و Story Elements
- تگ‌های معنایی
- تخمین دستهٔ لنز

بازشدن Inspector نباید تا پایان تحلیل AI متوقف بماند.

### ۶.۶. تحلیل زمانی کوتاه

یک فریم برای تشخیص حرکت کافی نیست. ShotLab می‌تواند هنگام Capture، بدون
ذخیرهٔ دائمی، یک بازهٔ کوتاه مثلاً یک ثانیه قبل و یک ثانیه بعد را تحلیل کند.

این تحلیل برای پیشنهاد موارد زیر استفاده می‌شود:

- Pan
- Tilt
- Dolly
- Tracking
- Zoom
- Handheld
- حرکت سوژه
- تغییر محسوس نور

نتایج باید با برچسب `Temporal Analysis` از تحلیل ثابت فریم تفکیک شوند.

### ۶.۷. اصلاح و تأیید

کاربر می‌تواند:

- تمام اطلاعات پیشنهادی را اصلاح کند.
- تگ سفارشی اضافه کند.
- یادداشت بنویسد.
- Draft را کنار بگذارد.
- فریم را تأیید کند.

بعد از تأیید:

- تصویر Captureشده در پوشهٔ پروژه ذخیره می‌شود.
- Thumbnail ساخته می‌شود.
- متادیتا در دیتابیس ثبت می‌شود.
- نسخهٔ مستقل JSON پروژه به‌روزرسانی می‌شود.
- Marker روی Timeline ظاهر می‌شود.
- Thumbnail در فهرست فریم‌های ثبت‌شده نمایش داده می‌شود.

## ۷. Taxonomy متادیتا

پیش از اتصال مدل AI باید واژگان استاندارد ShotLab طراحی شوند. این کار از
پراکنده‌شدن برچسب‌هایی مانند `Medium Shot`، `Mid Shot` و `Waist Shot` جلوگیری
می‌کند.

دسته‌های اصلی:

1. Framing
2. Camera
3. Composition
4. Subject
5. Environment
6. Lighting
7. Color
8. Focus
9. Mood
10. Motion
11. Story Elements
12. Technical Estimate
13. Custom Tags

هر مقدار استاندارد باید شناسهٔ مستقل از زبان داشته باشد:

```json
{
  "id": "lighting.low_key",
  "en": "Low-Key",
  "fa": "نورپردازی کم‌مایه"
}
```

زبان رابط می‌تواند فارسی یا انگلیسی باشد، اما دیتابیس همیشه شناسهٔ ثابت را
ذخیره می‌کند.

## ۸. دقت، منبع و Confidence

اطلاعات باید براساس نوع خود تفکیک شوند.

### ۸.۱. داده‌های اندازه‌گیری‌شده

- Timecode
- PTS
- Resolution
- Frame Rate
- Aspect Ratio
- Color Palette
- Brightness
- Contrast
- Saturation

### ۸.۲. داده‌های تخمینی

- فاصلهٔ کانونی احتمالی
- دستهٔ لنز
- جهت منبع نور
- زمان روز
- Mood
- Depth of Field
- نوع لوکیشن

هر پیشنهاد AI باید اطلاعات زیر را داشته باشد:

```json
{
  "value": "camera_left",
  "confidence": 0.78,
  "source": "ai",
  "edited_by_user": false
}
```

پس از اصلاح کاربر:

```json
{
  "value": "camera_right",
  "confidence": 1.0,
  "source": "user",
  "edited_by_user": true
}
```

اجرای مجدد تحلیل نباید اطلاعاتی را که کاربر اصلاح کرده است بدون اجازهٔ او
بازنویسی کند.

## ۹. صفحهٔ پروژه

صفحهٔ هر پروژه می‌تواند شامل موارد زیر باشد:

- نام پروژه
- اطلاعات اختیاری پروژه
- Cover انتخاب‌شده
- مدت و مشخصات فنی منبع، در صورت ثبت
- تعداد Captureها
- تاریخ ایجاد و آخرین ویرایش
- پنج رنگ نمایندهٔ پروژه
- Color Script
- گالری Captureها
- فیلتر داخلی پروژه
- دکمهٔ شروع یا ادامهٔ جلسهٔ Capture
- افزودن تصویر مستقل
- Backup و Export

فقط نام پروژه الزامی است و خالی‌بودن سایر اطلاعات باید در طراحی صفحه به‌صورت
طبیعی مدیریت شود.

## ۱۰. کارت پروژه و پنج رنگ نماینده

در صفحهٔ Library، هر پروژه با موارد زیر نمایش داده می‌شود:

- نام پروژه
- Cover انتخابی یا Cover خودکار
- تعداد Captureها
- آخرین تاریخ ویرایش
- پنج رنگ نماینده

پنج رنگ نباید با شمارش سادهٔ RGB انتخاب شوند. رنگ‌های Captureها باید در یک فضای
رنگی ادراکی مانند `CIELAB` خوشه‌بندی شوند. نرم‌افزار می‌تواند حذف رنگ‌های نزدیک
به سیاه و سفید را به‌صورت یک گزینه در اختیار کاربر بگذارد.

## ۱۱. Color Script

Color Script باید تغییرات رنگی Captureها را در طول زمان منبع نمایش دهد.

الزامات:

- موقعیت هر Capture متناسب با Timecode آن باشد.
- فاصله‌های فاقد Capture مشخص باقی بمانند.
- نرم‌افزار نباید از تعداد کمی نمونه، Color Script کامل و قطعی وانمود کند.
- دو حالت نمایش وجود داشته باشد:
  - `Discrete`: نمایش مستقل هر Capture
  - `Continuous`: Interpolation بین نمونه‌ها، فقط با اعلام اینکه نمایشی تخمینی
    است
- کلیک روی هر بخش، Capture مرتبط را باز کند.

## ۱۲. افزودن تصاویر مستقل

کاربر می‌تواند تصاویر مستقل را با Drag & Drop یا File Picker اضافه کند.

نوع منبع هر رکورد باید مشخص باشد:

```text
Video Capture
Imported Image
```

تصویر مستقل Timecode ندارد، اما می‌تواند اطلاعات اختیاری زیر را داشته باشد:

- نام منبع
- نام فیلم یا پروژه
- عکاس یا فیلم‌بردار
- سال
- توضیح
- تگ‌ها

تصویر پس از ورود، همان مراحل تحلیل، اصلاح و تأیید را طی می‌کند.

## ۱۳. جست‌وجو

### ۱۳.۱. جست‌وجوی ساختاریافته

جست‌وجوی دقیق و سریع براساس:

- پروژه
- Framing
- Camera Angle
- Interior یا Exterior
- Day یا Night
- Lighting
- Color
- Mood
- Subject
- Tags
- Motion
- محدودهٔ Timecode

این بخش می‌تواند با SQLite و ایندکس‌های مناسب اجرا شود.

### ۱۳.۲. جست‌وجوی معنایی

کاربر باید بتواند با زبان طبیعی فارسی یا انگلیسی جست‌وجو کند:

> فضای گرم و صمیمی با شخصیتی تنها کنار پنجره

این جست‌وجو با Embeddingهای تصویری و متنی و Vector Index لوکال انجام می‌شود.

## ۱۴. Reference Board

کاربر می‌تواند فریم‌هایی از چند پروژه را انتخاب و در یک Board قرار دهد:

- مرتب‌سازی دستی
- یادداشت برای هر فریم
- عنوان و توضیح Board
- نمایش رنگ‌ها و تگ‌های انتخابی
- خروجی PDF یا تصویر
- خروجی قابل اشتراک برای تیم

## ۱۵. زبان و رابط کاربری

- رابط نرم‌افزار فارسی و انگلیسی است.
- زبان از Settings قابل تغییر است.
- رابط فارسی باید RTL و رابط انگلیسی LTR باشد.
- طراحی مدرن، حرفه‌ای و کم‌اشباع باشد.
- الگوی بصری می‌تواند از نرم‌افزارهایی مانند Blender الهام بگیرد.
- چیدمان باید برای مانیتورهای کاری و استفادهٔ طولانی مناسب باشد.
- Shortcutها باید قابل مشاهده و در نسخه‌های بعدی قابل شخصی‌سازی باشند.

## ۱۶. ذخیره‌سازی

ساختار پیشنهادی هر پروژه:

```text
projects/
└── <project-id>/
    ├── project.json
    ├── captures/
    │   ├── full/
    │   └── thumbnails/
    ├── imported-images/
    ├── boards/
    └── cache/
```

دیتابیس اصلی، اطلاعات ساختاریافته و ایندکس جست‌وجو را نگهداری می‌کند.
`project.json` نسخه‌ای مستقل و قابل بازیابی از اطلاعات اصلی پروژه است.

فایل ویدئوی منبع و مسیر دائمی آن در این ساختار یا دیتابیس ذخیره نمی‌شوند.

## ۱۷. Backup، Export و Import

فرمت قابل انتقال پیشنهادی:

```text
MyProject.shotlab
```

این فایل می‌تواند یک Archive شامل موارد زیر باشد:

```text
manifest.json
project.json
captures/
imported-images/
boards/
database.sqlite
preview.jpg
```

ویدئوی منبع در Backup استاندارد قرار نمی‌گیرد.

گزینه‌های Export:

- اطلاعات و Thumbnailها
- تصاویر کامل و اطلاعات
- Board یا مجموعهٔ انتخابی

هر Backup باید شامل این موارد باشد:

- Schema Version
- ShotLab Version
- AI Model Version
- تاریخ Export
- Checksum فایل‌ها

Import باید:

- سازگاری نسخه را بررسی کند.
- در صورت نیاز Migration انجام دهد.
- از ایجاد رکوردهای تکراری جلوگیری کند.
- نتیجهٔ Import را پیش از نهایی‌شدن به کاربر نشان دهد.
